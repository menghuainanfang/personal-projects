# v0.1 基线审计

审计日期：2026-10-11。公开基线提交为 `9aca90122e6c960fc4caae8c071801151d0ce46d`，应用位于 `projects/readingos`。基线使用实际 Electron 程序、生产构建、SQLite 与原创 PDF/EPUB；没有读取个人书库。

## 实际状态

Electron 44.7、React 19、TypeScript、Vite、Node 内置 SQLite。PDF.js 5.4.624 提供文字层与渲染，epub.js 0.3.93 提供 CFI、重排与高亮；Tiptap 保存主读后感及日志。Windows 当前用户 NSIS 安装包已经发布。数据结构 v1 包含 14 张表，备份同时包含数据库与管理的原书副本。

导入、纸质书、搜索/状态筛选、封面、主读后感历史、日志、洞见来源、实践反馈、计划/实际完成、PDF 绘图、EPUB 高亮、书签、进度、备份恢复与 Markdown 导出均已存在。复测 8 项数据测试、12 项实际桌面流程、生产构建通过，没有观察到阻断这些流程的缺陷。

## 本版应解决的问题

- 书架进入阅读需先开书籍主页；可增加独立的继续阅读入口。
- 阅读排版偏好仅存在于会话，重开后丢失；需要按逻辑书保存，版本仍各自保存位置。
- 日志的关联批注入口只打开阅读器，没有传入准确位置；需要解析对应 asset 的原始锚点。
- 选文只能先高亮再改评论；缺少选文直接写批注和批注引用日志入口。
- 内容区域的卡片边框与装饰较多，主读后感的正文层级不够突出。侧栏占用较宽，缩放情况下需要调整。

主读后感历史保存完整正文，随写作增长；这是真实容量限制，不在本次改为增量存储。PDF 固定页和 EPUB 内容树锚点继续保留，不更换格式。
